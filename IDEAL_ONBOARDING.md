# Palo Alto Networks Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь:
network/security admin, управляющий одним PAN-OS firewall напрямую и/или
парком firewalls через Panorama.

## 1. Credential type

Две независимые формы, ни одна не обязательна для другой:

- **PAN-OS firewall:** `host` (напр. `https://fw01.company.com`) +
  `username` + `password` (коннектор обменивает их на API key через
  `type=keygen` при подключении и хранит только полученный ключ).
- **Panorama:** `host` + `username` + `password` (тот же keygen-обмен).

## 2. Идеальный флоу

1. **Первое открытие** — `Empty` с двумя равнозначными путями: "Подключить
   PAN-OS firewall", "Подключить Panorama" — не визард, два независимых
   входа (клиент использует одну или обе поверхности).
2. **Форма PAN-OS** — `host` + `username` + `password` (password). Подсказка
   (в help-модалке): где взять права (Administrator role с XML API
   доступом), что делает коннектор при подключении (одноразовый keygen-обмен,
   не хранит пароль).
3. **Форма Panorama** — `host` + `username` + `password` (password). Та же
   логика keygen-обмена. Подсказка: Panorama управляет device groups —
   после подключения появится список managed devices.
4. **Ошибка неверных данных** — явное сообщение "Palo Alto Networks
   rejected these credentials" с призывом проверить host/username/password,
   без утечки исходных данных в лог.
5. **После первого успешного подключения** — сайдбар показывает список
   подключений (с их kind: panos/panorama) и кнопки навигации к
   Security Rules / Panorama Overview / Health audit; секция подключения
   остаётся доступной ниже для добавления ещё одного firewall/Panorama.
6. **Disconnect** — только через единую кнопку "App settings" в сайдбаре,
   не дублируется рядом с формами подключения.

## 3. Специфичные для PAN-OS ошибки, которые UI обязан объяснять по-человечески

- **Просроченный/невалидный API key** — коннектор автоматически повторяет
  keygen при обнаружении кода ошибки `403`/`invalid key`, не требуя от
  пользователя вручную переподключаться.
- **`commit` в процессе** — если предыдущий commit ещё выполняется, PAN-OS
  отклоняет новый commit кодом ошибки; UI явно говорит "Изменения уже
  применяются, подождите" вместо технической ошибки XML API.
- **Заблокированное правило после reorder** — предупреждение перед
  reorder/commit, что новый порядок правил вступит в силу только после
  commit, а не сразу при сохранении черновика.
